## 출력 파일 (Python, UTF-8) — 지정된 경로에 저장
```python
# -*- coding: utf-8 -*-
CAT = dict(
  id='<지정 id>', icon='<이모지 1개>', name='<과제명>', sub='<세부 트랙을 · 로 나열한 한 줄>',
  what="<이 과제가 무엇인지 모르는 사람을 위한 쉬운 설명 3~6문장. HTML 허용은 <b>만. 핵심 용어는 괄호로 풀어쓴다>",
  tracks=[('<코드>','<트랙명>'), ...],      # 2~5개. 코드는 id 접두 + 숫자/알파벳 (예: 'eth1','eth2')
  status=[('<kind>','<현재 핵심 상태 한 문장~두 문장, <b> 허용>'), ...],   # 4~6개. 가장 최근 Weekly(10/26~10/30 또는 마지막 언급) 기준. 언제 이후 보고가 없는지도 적는다 (예: "(8월 이후 Weekly 미보고)")
)
ITEMS = [
  dict(c='<id>', t='<트랙코드>', d='YYYY-MM-DD', w='<주차 라벨>', k='<kind>', title='<제목>', body='<본문>', tags=['<키워드>', ...]),
  ...
]
```
- kind: done(완료·확정) / prog(진행 중) / plan(계획·예정) / risk(이슈·리스크) / mile(마일스톤, 큰 사건) / info(정보·시사점)
- d(날짜): 본문에 날짜가 명시되면 그 날짜(예: "4/23 방한" → 2026-04-23), 없으면 그 주차의 시작일(월요일). 12월 주차는 2025년.
- w(주차 라벨): 아래 목록의 문자열과 **정확히** 일치해야 함:
  12/8~12, 12/15~19, 12/22~26, 12/29~1/2, 1/5~9, 1/12~16, 1/19~23, 1/26~30, 2/2~6, 2/9~13, 2/16~20, 2/23~27, 3/2~6, 3/9~13, 3/16~20, 3/23~27, 3/30~4/3, 4/6~10, 4/13~17, 4/20~24, 4/27~5/1, 5/4~8, 5/11~15, 5/18~22, 5/25~29, 6/1~5, 6/15~19, 6/22~26, 6/29~7/3, 7/6~7/10, 7/13~7/17, 7/20~7/24, 7/27~7/31, 8/3~8/7, 8/10~8/14, 8/17~8/21, 8/31~9/4, 9/7~9/11, 9/14~9/18, 10/5~10/9, 10/12~10/16, 10/19~10/23, 10/26~10/30
  (H1 파일 헤더는 "12/8~12/12" 처럼 돼 있을 수 있음 → 위 목록 표기로 변환. H2는 "7/6~7/10" 그대로.)
- title: 60자 이내. 날짜·상대·핵심 숫자를 담아 그 자체로 읽히게 (예: "Maersk LNG 구매 총괄 방한 (4/23): '28년 신조 6척 2.8만톤 기반 협력 공감").
- body: 1~5문장. 원문의 사실·숫자·고유명사를 그대로 살리되 보고체("~하였습니다")는 개조식("~함", "~검토 중")으로. 핵심 숫자·결정은 <b>로. 다른 사건을 참조할 때는 괄호로 시점을 적는다 (예: "(8/20 EPD 경영진 미팅 후속)"). 허용 HTML은 <b>, <br>뿐. 따옴표는 큰따옴표 사용 시 파이썬 문자열 충돌에 주의.
- tags: 검색용 키워드 3~8개 (회사명, 기관명, 숫자, 핵심 용어). 한글/영문 표기 둘 다 있으면 둘 다.
- 원칙: **Weekly에 없는 사실을 만들지 말 것.** 같은 주차에 같은 세부 주제의 불릿이 여럿이면 한 항목으로 합쳐도 되고, 다른 주제면 나눈다. 과제가 언급된 모든 주차가 최소 1개 항목으로 반영되어야 한다(누락 금지). 예상 항목 수는 과제당 15~45개.
- 파일 끝에 `COVERAGE = "<이 과제가 언급된 주차 수> / 언급 없는 주차: ..."` 문자열 상수를 추가.
